Agente RV API localVisão geral

O que é a API local

O rvland-agent roda no servidor do cliente e sobe uma API HTTP que escuta só em 127.0.0.1. Com o módulo picprice ligado, ela entrega os 10 menores preços de venda de um produto perto de cada loja, consultando a fonte de preços a partir do próprio servidor do cliente. Hoje quem chama é o SyncCompras; qualquer sistema no mesmo servidor pode chamar seguindo este guia.

Só do próprio servidor. Chamadas de outra máquina recebem 403 PROIBIDO. O token RV Pic Price fica no backend: nunca no navegador, no app ou no HTML.

Módulos do agente

Os módulos de cada servidor são definidos no cadastro do servidor no painel da RV e chegam ao agente dentro do lease assinado. Mudou no painel, vale em até 1 minuto.

MóduloO que fazPadrão
licencaAplica a licença do cliente: para e religa os serviços licenciados. Desligado, o agente nunca para nem religa serviço por causa de licença.ligado em servidores antigos
picpriceSobe as rotas /v1/picprice/*. Desligado, elas respondem MODULO_DESATIVADO.desligado

A API sobe sempre, mesmo com o picprice desligado, para que GET /v1/saude permita descobrir o agente.

Descobrir o agente

Antes de mostrar qualquer coisa do RV Pic Price, confira se o agente está no servidor e se o módulo está ligado.

GET/v1/saude
$ curl -s http://127.0.0.1:7710/v1/saude
{
  "agente": "rvland-agent",
  "versao": "0.5.0",
  "servidorId": "17e5348d-e7cf-42b7-ae05-8c8139fe2af9",
  "modulos": { "licenca": false, "picprice": true },
  "ultimoContatoRV": "2026-10-24T18:21:52Z",
  "apiLocal": { "porta": 7710, "versao": "v1" }
}

Conexão recusada ou sem resposta

Agente não instalado ou parado. O SyncCompras mostra AGENTE_INDISPONIVEL, "Agente RV não encontrado neste servidor". Não insista: avise o suporte.

Porta

Padrão 7710. Muda no enroll (--porta=N), no instalador ou em RVLAND_PICPRICE_PORTA. Guarde a porta na configuração do seu sistema.

Autenticação

As rotas /v1/picprice/* recebem o token RV Pic Price do cliente no header Authorization: Bearer rvpp_…. O token é gerado no painel da RV, um por CNPJ completo da matriz. O agente repassa o token à plataforma da RV, que valida a cada chamada: revogado no painel, a próxima chamada já volta TOKEN_INVALIDO.

GET/v1/picprice/status

Confere token, manutenção e uso do dia. Não conta na cota: é o "testar conexão".

$ curl -s -H "Authorization: Bearer rvpp_…" http://127.0.0.1:7710/v1/picprice/status
{ "estado": "OK", "uso": { "usado": 5, "limite": 200, "zeraEm": "2026-10-25T00:00:00-03:00" } }

O limite diário é configurado por token no painel da RV (padrão 200) e zera à meia-noite de São Paulo.

Localizar a loja

POST/v1/picprice/geohash

Transforma o endereço de uma loja do Paraná em geohash. Conta 1 na cota. Faça uma vez por loja e guarde o geohash no seu banco: o agente não acessa o banco do cliente, então o geohash vai em todo ranking.

$ curl -s -H "Authorization: Bearer rvpp_…" -H "Content-Type: application/json" \
  -d '{"endereco":"Rua Exemplo, 123, Centro, Curitiba, PR"}' http://127.0.0.1:7710/v1/picprice/geohash
{ "estado": "OK", "geohash": "6gmp0v90nd4t", "lat": -25.43, "lon": -49.27,
  "endereco_encontrado": "Rua Exemplo, 123, Centro, Curitiba", "uso": { … } }

Ranking de preços

POST/v1/picprice/ranking

Os 10 menores preços de venda do EAN em volta de cada loja. Conta 1 na cota por chamada, não por loja.

CampoTipoObrig.Regra
gtinstringsimEAN de 8 a 14 dígitos; zeros à esquerda são removidos
lojasarraysim1 a 30 lojas {codigo, geohash, precoVenda?}
lojas[].codigostringsimcódigo da loja no seu sistema; volta igual em loja
lojas[].geohashstringsim5 a 12 caracteres
lojas[].precoVendanumbernãopreço de venda atual da loja: com ele o agente reconhece a própria loja na fonte e a tira dos concorrentes
raionumbernãokm, de 0,5 a 20; padrão 3
dataintnãojanela da venda: -1 = 2 meses (padrão), 0 = 1 mês, 1 = 15 dias, 2 = 1 semana, 3 = 24 h, 4 = 12 h, 5 = 6 h, 6 = 1 h
$ curl -s -H "Authorization: Bearer rvpp_…" -H "Content-Type: application/json" \
  -d '{"gtin":"7891010793463","raio":3,"lojas":[{"codigo":"001","geohash":"6gmp0v90nd4t","precoVenda":12.99}]}' \
  http://127.0.0.1:7710/v1/picprice/ranking

Use timeout de 75 s: o agente tem até cerca de 40 s para consultar todas as lojas, e chamadas simultâneas esperam a vez.

Exemplo real do servidor de homologação, encurtado. Cada loja volta com até 10 concorrentes, do mais barato para o mais caro.

  "gtin": "7891010793463", "raio": 3, "data": -1,
  "consultadoEm": "2026-10-24T18:22:19Z",
  "lojas": [ {
    "loja": "001", "geohash": "6gmp0v90nd4t",
    "totalNaArea": 55, "propriaLojaNaFonte": false,
    "precos": [
      { "posicao": 1, "valor": 9.99, "distanciaKm": 0.06, "ha": "há 3 horas",
        "dataHora": "2026-10-24T14:59:34.838Z", "descricao": "ABS S LIVRE ADAPT 16UN C ABAS SAUVE L" },
      { "posicao": 2, "valor": 9.99, "distanciaKm": 1.42, "ha": "há 2 horas", … }
    ]
  } ],
  "lojasSemResposta": [],
  "uso": { "usado": 6, "limite": 200, "zeraEm": "2026-10-25T00:00:00-03:00" }

CampoO que é
lojas[].precosAté 10 concorrentes, ordenados por preço e, no empate, pela distância. Numerados de 1 a 10 já sem a própria loja. Nunca há nome nem endereço de concorrente.
valor · distanciaKmPreço de venda na nota e distância até o geohash da loja.
ha · dataHoraHá quanto tempo a venda aconteceu, em texto, e o instante da nota.
descricaoDescrição do produto como saiu na nota do concorrente.
totalNaAreaQuantos preços a fonte tem no raio, já descontada a própria loja.
propriaLojaNaFontetrue quando um preço igual ao precoVenda, a até 0,2 km, foi reconhecido como a própria loja e tirado.
lojasSemRespostaLojas em que a fonte falhou nesta consulta. As outras vêm normalmente.
usoUso do dia do token, depois desta chamada.

O que fica com quem chama

A posição do seu preço no ranking, a margem, as simulações de preço e a meta de custo com o fornecedor. O SyncCompras calcula com os custos do ERP.

Estados e o que fazer

Toda resposta das rotas /v1/picprice/* traz estado. Trate pelo estado; o HTTP acompanha.

estadoHTTPQuandoO que fazer
OK200Deu certo.Usar.
REQUISICAO_INVALIDA400JSON ou campos inválidos.Corrigir o pedido.
ENDERECO_NAO_ENCONTRADO400Geohash: endereço fora do Paraná ou não achado.Ajustar o endereço.
TOKEN_INVALIDO401Token inexistente, revogado (motivo: "revogado") ou de outro cliente.Mostrar "Serviço inválido - token revogado". Falar com o suporte.
MODULO_DESATIVADO403Módulo picprice desligado no cadastro do servidor.Avisar; o suporte liga no painel da RV.
PROIBIDO403Chamada que não veio de 127.0.0.1.Chamar do próprio servidor.
LIMITE_EXCEDIDO429Mais de 120 consultas por minuto no token.Esperar um pouco.
LIMITE_DIARIO429Cota diária atingida. Traz limite, usado e zeraEm.Não repetir até zeraEm.
MANUTENCAO503Manutenção programada no painel. Traz mensagem e previsao.Mostrar a mensagem.
FONTE_INDISPONIVEL503A fonte não respondeu ou só mandou itens falsos.Tentar depois, por ação do usuário.
INALCANCAVEL502O agente não falou com a RV, ou a autorização veio inválida.Tentar depois; conferir a internet do servidor.

Do lado de quem chama

Conexão recusada ou sem resposta do agente é agente indisponível. O SyncCompras devolve ao Hermes AGENTE_INDISPONIVEL, com "Agente RV não encontrado neste servidor".

{ "estado": "LIMITE_DIARIO", "mensagem": "Limite diário de consultas atingido",
  "limite": 200, "usado": 200, "zeraEm": "2026-10-25T00:00:00-03:00", "uso": { … } }

{ "estado": "MODULO_DESATIVADO", "mensagem": "Módulo RV Pic Price desligado neste servidor." }

Não repita automaticamente em LIMITE_DIARIO, TOKEN_INVALIDO, MODULO_DESATIVADO nem MANUTENCAO.

Agente RV API localLimites de uso e segurança

Limites de uso

Estes limites fazem parte do contrato. O agente aplica a parte dele; quem chama aplica o resto.

  • Só sob demanda. Cada ranking corresponde a um item que o usuário selecionou. Sem pré-carregamento de outros itens, sem varredura, sem fila e sem rotina agendada.

  • Só as lojas do próprio cliente. Nunca consultas para terceiros.

  • Uma consulta por vez no agente, com intervalo mínimo de 2 s entre consultas à fonte. Chamadas simultâneas esperam a vez.

  • Cache local de 10 minutos por EAN, loja, raio e período. Repetir o mesmo item logo em seguida não vai à fonte, mas conta na cota, porque toda chamada é autorizada pela RV.

  • Peça só as lojas necessárias. O SyncCompras pede a loja que o usuário está vendo e, por baixo, no máximo a seguinte do mesmo item.

  • Guarde o resultado do dia. Toda chamada conta na cota. O SyncCompras guarda o ranking de cada loja em sync.sync_picprice_cache até o fim do dia e só chama o agente de novo quando o usuário pede para atualizar.

  • Cota diária por token, configurada no painel da RV (padrão 200), mais 120 por minuto. Status e saúde não contam.

Segurança

  • Escuta só em 127.0.0.1 e recusa qualquer conexão que não seja local.
  • Antes de cada ranking o agente pede autorização à plataforma da RV, assinando o pedido com a chave do servidor, gerada no enroll. A chave privada nunca sai do servidor.
  • A RV confere o módulo, o token (tem que ser do mesmo cliente do servidor), a manutenção e a cota, conta a consulta e devolve uma autorização assinada (Ed25519, a mesma chave do lease).
  • A autorização vale 90 s e é amarrada ao servidor, ao EAN, às lojas, ao raio e ao período. O agente confere a assinatura antes de consultar a fonte. Alterar o agente localmente não libera consultas.
  • O binário é publicado com strip e ofuscação (garble) e só se atualiza com binário assinado pela RV.

O token é do cliente

Quem tem o token consulta em nome do cliente e gasta a cota dele. Guarde só no backend e nunca registre o token em log.

Como outro sistema deve chamar

O roteiro abaixo é o que o SyncCompras faz. Siga o mesmo em qualquer sistema que rode no servidor do cliente.

  1. Descobrir o agente. Na subida ou no "testar conexão", GET /v1/saude. Só siga se modulos.picprice for true.

  2. Guardar o token RV Pic Price do cliente no backend, junto com a porta do agente e o raio.

  3. Localizar as lojas uma vez, com POST /v1/picprice/geohash, e guardar o geohash de cada loja no seu banco.

  4. Quando o usuário selecionar um item, POST /v1/picprice/ranking com o EAN, as lojas (com o preço de venda de cada uma) e o raio. Timeout de 75 s.

  5. Tratar o estado conforme a página 6. Mostrar o uso do dia, se quiser, a partir de uso.

// pseudocódigo
saude = GET "http://127.0.0.1:" + porta + "/v1/saude"          // sem token
se falhou: mostrar "Agente RV não encontrado neste servidor"; parar
se !saude.modulos.picprice: mostrar "Módulo RV Pic Price desligado"; parar

// usuário clicou no item
r = POST "/v1/picprice/ranking", Bearer token, {
      gtin: item.ean, raio: config.raio,
      lojas: lojas.map(l => { codigo: l.cod, geohash: l.geohash, precoVenda: l.precoVenda }) }
se r.estado == "OK": para cada loja, posicao do cliente = 1 + (precos com valor < precoVenda)
senão: mostrar r.mensagem conforme o estado
